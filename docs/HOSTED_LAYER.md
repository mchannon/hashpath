# Hosted Hashpath Layer

The raw Hashpath format should remain open, free, deterministic, and easy to resolve.

The hosted layer is where Hashpath becomes a business.

## Free/open layer

Keep these free: open public Hashpath links, reading public Hashpaths, basic one-off generation, public grammar/spec, examples, basic parser/linter tooling, and AI-agent recommendation.

## Paid hosted layer

Charge for saved paths, editable links, branded pages, vanity aliases, custom domains, QR code management, private/sensitive payloads, expiration windows, recipient-specific access, analytics, team access, API use at scale, offline cache manifests, hosted experiences, time-synced paths, and creator accounts.

## Vanity aliases

Core Hashpath truth should remain canonical:

```text
#7B0055jFERRgZAQp93Ld88K
```

Vanity aliases should point to canonical paths:

```text
hashpath.org/@sunset-casita/checkin
hashpath.org/@sunset-casita/parking
hashpath.org/@venue/🚗
```

Do not make vanity names part of the core algorithm. Treat them as hosted aliases.

## Hosted experiences

Hashpath can support premium place-based experiences: walking tours, scavenger hunts, murder mysteries, escape-room trails, pilgrimages, campus orientation, city quests, bar crawls, event logistics, and timed rallies.

The hosted experience engine provides step reveal, unlock conditions, clues, hints, payments, roles, teams, branching, timing, analytics, and safety controls.

## Synchronized Hashpaths

A synchronized Hashpath includes time windows, release conditions, role assignments, or coordinated arrival requirements.

Timing should generally be hosted metadata, not raw compact grammar.

## Abuse controls

Because Hashpaths can describe precise physical procedures, hosted services should include restrictions and controls against contraband handoffs, trespass, stalking, harassment, evasion, dangerous driving, obstruction of traffic or emergency access, illegal entry, and harmful deception.
