## Design principles

Hashpath should be:

- compact
- shareable
- app-readable
- human-readable
- map-compatible
- access-aware
- fallback-aware
- privacy-aware
- useful without forcing a login

## Roadmap

Possible directions:

- richer examples
- schema validation
- editor/preview app
- reader mode
- QR-code publishing
- hosted Hashpath layer
- private/expiring access details
- AI-agent conversion from natural language
- BPS/local anchor support
- Hashsite integration
- import/export formats
- printable arrival cards
- venue/property workflows

## Product center

Hashpath is not a footnote to Hashsite.

Hashsite names places compactly.

Hashpath turns arrival procedures into compact, structured, shareable instructions.
